# Vision de GAMAD Core

## Mission

GAMAD Core est le système nerveux commun de l’écosystème numérique GAMAD.

Il maintient les fonctions dont la fragmentation entre plusieurs produits créerait des identités concurrentes, des droits incohérents, des contrats incompatibles, des preuves impossibles à reconstruire ou une dépendance excessive à un satellite.

## Ce que le Core fournit

- une identité canonique commune ;
- l’authentification, les sessions et les niveaux d’assurance ;
- les organisations, autorités, mandats et délégations communs ;
- les décisions d’autorisation transversales ;
- les contrats, événements et attestations partagés ;
- le catalogue des produits et leurs relations avec les identités ;
- l’audit, les preuves d’intégrité, les risques, incidents, secrets et mécanismes de continuité ;
- un Moteur de Matching consommable par plusieurs satellites ;
- la fédération des satellites et le futur Portail GAMAD.

## Ce que le Core ne doit pas absorber

Le Core ne devient pas :

- la base publicitaire de Wasplex ;
- le stockage documentaire de GamaDrive ;
- la caisse ou la base des ventes d’IKOMA ;
- la messagerie de G-Mail ;
- le dossier métier complet de G-Business ;
- un dossier médical universel ;
- une réputation générale des personnes ;
- une super-application remplaçant tous les satellites.

## Formule directrice

> Un seul corps numérique GAMAD, une identité commune, une porte d’entrée commune et plusieurs organes spécialisés qui coopèrent sans fusionner leurs bases.

## Responsabilité des satellites

Chaque satellite conserve :

- son compte produit local ;
- ses données détaillées ;
- ses abonnements, quotas et transactions ;
- ses règles métier ;
- son stockage ;
- son interface ;
- son support et son exploitation.

Le Core fournit les références, contrats et contrôles communs nécessaires à leur coopération.

## Règle d’évolution

Un besoin expérimenté dans un satellite peut être proposé au Core lorsqu’il devient réellement commun, durable et transversal.

Il ne devient pas automatiquement une capacité du Core. La décision se fonde sur l’utilité commune, les frontières de données, les consommateurs réels, le coût d’exploitation et les tests.
